# Personal Flight Log

비행을 직접 기록하고 지도, 통계, 타임라인, `PLAY MY JOURNEY`로 다시 보는 개인용 비행 아카이브입니다. 사이트를 열면 항상 전용 기록 관리 화면에서 시작하며, 여러 비행을 연속으로 추가·수정·삭제한 뒤 `내 비행 기록 보기`를 눌러 전체 아카이브로 이동합니다.

```text
direct flight entry
→ current page memory
→ map / statistics / rankings / timeline / journey replay
```

## 주요 기능

- 비행 추가, 수정, 단건 즉시 삭제
- 여러 비행을 연속 입력하는 기록 화면과 명시적인 전체 아카이브 전환
- IATA·영문 공항명·도시·국가와 검토된 한국어 별칭으로 찾는 로컬 공항 자동완성
- 현재 데이터베이스에 없는 역사적 공항의 직접 입력과 선택적 좌표 입력
- 국가 코드에 따른 국내선/국제선 자동 구분
- 연도·국내선·국제선 필터와 비행 편수, 거리, 국가, 공항 통계
- 사용자 정의 SVG 세계 지도, 노선 상세, 팬·휠·핀치 확대, 세계 경도 래핑
- 국가·도시·공항·운항사 순위와 최신순 Flight Timeline
- 기종별 실루엣, 카메라 추적, 버스·페리 환승을 포함한 시간순 여정 재생
- 버전이 있는 JSON 백업·복원(병합 또는 교체)과 한국어 CSV 내보내기
- 기존 CSV/XLS/XLSX 기록의 선택적 1회 마이그레이션
- 360px 모바일부터 넓은 데스크톱까지 대응

## 세션 기록과 개인정보

비행 기록은 **현재 페이지가 열려 있는 동안의 메모리**에만 유지됩니다. 새로고침하거나 페이지를 닫았다 다시 열거나 새 탭을 열면 빈 기록 화면에서 다시 시작합니다. 계정, 로그인, 애플리케이션 백엔드, 서버 데이터베이스, 비행 기록 업로드 API는 없습니다. 추가·수정·삭제와 공항 검색은 브라우저 안에서 처리됩니다.

기록을 다음 방문에도 보존하려면 페이지를 떠나기 전에 `데이터 관리`에서 JSON 백업이나 CSV 내보내기를 사용하세요. JSON 복원과 기존 CSV/XLS/XLSX 가져오기도 현재 페이지 세션만 채우며, 가져온 뒤 새로고침하면 다시 초기화됩니다. 자동 저장이나 기기 간 동기화는 없습니다.

이전 개발 버전이 만들었던 `personal-flight-log-manual` IndexedDB는 V1.3에서 열거나 읽거나 자동 삭제하지 않습니다. 과거 데이터가 화면에 다시 나타나지 않으며, 시작 동작도 해당 데이터베이스의 삭제 성공 여부에 의존하지 않습니다. 필요하면 브라우저의 사이트 데이터 관리 기능으로 직접 정리할 수 있습니다.

개인 백업과 CSV 내보내기 파일은 Git에 추가하거나 프로젝트의 `src`/`dist` 안에 두지 마세요. 이 저장소는 루트의 비행 CSV·Excel 파일, 로컬 참조 파일, `flight-log-backup-YYYY-MM-DD.json` 파일을 무시하고 개발/미리보기 서버에서도 직접 제공하지 않도록 막습니다.

## 화면 이동 정책

- 사이트 시작·새로고침·재방문·새 탭은 항상 기록 0개인 기록 관리 화면에서 시작합니다.
- 같은 페이지 안에서 기록 관리 화면과 전체 아카이브를 오가는 동안에는 현재 세션 기록이 유지됩니다.
- 저장 후에도 자동으로 지도·통계 화면으로 이동하지 않습니다.
- 한 편 이상 저장하면 `내 비행 기록 보기`가 나타납니다.
- 전체 아카이브는 `내 비행 기록 보기`를 누를 때만 열리며, 마지막 화면을 별도 환경설정으로 저장하지 않습니다.
- 전체 아카이브의 `기록 관리`로 기록 화면에 돌아갈 수 있고, `+ 비행 추가`는 기존처럼 현재 화면에서 바로 추가 대화상자를 엽니다.
- 기록 화면의 개별 `삭제`는 한 번의 클릭으로 현재 세션에서 즉시 삭제됩니다. `데이터 관리`의 `모든 비행 기록 삭제`와 JSON 교체 확인은 기존 보호 절차를 유지합니다.

## 백업, 복원, 이동

`데이터 관리`에서 다음 작업을 할 수 있습니다.

- **JSON 백업**: 안정된 ID, 날짜, 입력 내용, 공항 이름·도시·국가·좌표 스냅샷을 모두 저장합니다.
- **JSON 복원**: 내용을 먼저 검증한 뒤 현재 세션 기록과 병합하거나 전체 교체합니다. 병합 시 같은 ID는 `updatedAt`이 더 새로운 기록만 반영됩니다. 새로고침하면 복원 기록도 사라집니다.
- **CSV 내보내기**: UTF-8 BOM이 포함된 한국어 CSV를 만들며 원래 CSV 기반 Flight Log 파서와 호환됩니다.
- **기존 CSV / Excel 가져오기**: 파일을 로컬에서만 읽고 확인 후 현재 세션에 추가합니다. 가져온 기록도 새로고침하면 사라집니다.
- **모든 기록 삭제**: 강한 확인을 거친 뒤 현재 세션의 비행 기록을 비웁니다.

## 기록 스키마

각 기록은 변경되지 않는 문자열 ID와 `createdAt`/`updatedAt`, 스키마 버전을 가집니다. 날짜는 시간대 변환이 없는 `YYYY-MM-DD` 날짜 전용 값입니다. 출발·도착 공항은 IATA, 공항명, 도시, ISO 국가 코드, 표시 국가명, 위도·경도를 저장 당시 스냅샷으로 보존합니다. 이후 공개 공항 데이터가 갱신되어도 기존 기록을 자동으로 다시 쓰지 않습니다.

현재 공항 목록에 없는 공항도 저장할 수 있습니다. 좌표가 없으면 기록·통계·타임라인에는 남고 지도 거리와 재생 기하에서만 제외됩니다. 국가 코드를 알 수 없는 직접 입력 공항은 통계를 임의로 만들지 않도록 국내선 또는 국제선을 사용자가 선택해야 합니다.

## 공항 데이터

좌표와 검색 메타데이터는 [OurAirports public-domain data](https://ourairports.com/data/)에서 한 번에 생성합니다.

- 작은 좌표 인덱스는 지도와 분석에서 즉시 사용합니다.
- 공항명·도시·국가가 포함된 검색 인덱스는 추가/수정 화면을 열 때만 지연 로드합니다.
- 사용자 입력 중 외부 공항 API를 호출하지 않으며 원본 CSV를 배포하지 않습니다.
- `Intl.DisplayNames`가 있으면 ISO 국가 코드를 한국어 국가명으로 표시하고, 없으면 코드로 대체합니다.

한국어 검색은 생성된 OurAirports 값을 번역하거나 덮어쓰지 않고, 별도로 검토한 작은 로컬 별칭 overlay를 검색 키로 더합니다. 현재는 대한민국 주요 여객 공항과 회귀 테스트에 쓰는 주요 국제 허브를 우선하며 모든 공항의 한국어 이름을 제공한다고 주장하지 않습니다. 예를 들어 `인천`, `서울`, `김포`, `부산`, `김해`, `제주`, `로스앤젤레스`, `도쿄`, `오사카`를 검색할 수 있습니다. 이 파일은 생성 데이터와 분리되어 월간 OurAirports 갱신에 덮어써지지 않으며, 입력 중 외부 번역·지오코딩 요청을 보내지 않습니다.

수동 갱신:

```bash
npm run update-airports
npm run lint
npm run test
npm run typecheck
npm run build
```

`.github/workflows/update-airports.yml`은 매월 1일 좌표와 검색 인덱스를 함께 검증합니다. 관련 생성 파일이 달라질 때만 자동화 브랜치에 반영하고 검토 가능한 PR을 열며 `main`에 직접 쓰지 않습니다. 이 유지보수 작업은 현재 페이지의 개인 비행 기록에 접근하지 않습니다.

## 로컬 개발

Node.js 22 이상을 권장합니다.

```bash
npm ci
npm run dev
```

최종 검증:

```bash
npm run lint
npm run test
npm run typecheck
npm run build
npm run preview
```

개발 서버와 미리보기 서버는 기본적으로 `127.0.0.1`에만 바인딩됩니다.

## GitHub Pages 호환성

애플리케이션은 정적 Vite 빌드이며 서버 런타임이 필요 없습니다. `.github/workflows/deploy.yml`은 `main` 변경 시 `npm ci → lint → test → typecheck → build`를 실행하고 `dist`만 GitHub Pages 아티팩트로 올리도록 준비되어 있습니다. 프로젝트 저장소와 `<username>.github.io` 저장소의 base 경로를 GitHub Actions 환경에서 자동으로 구분합니다.

이 로컬 Manual V1 작업에서는 원격 생성·변경, GitHub 인증, 커밋, 푸시, 배포를 수행하지 않습니다.
